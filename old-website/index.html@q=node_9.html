Installation

Submitted by Piotr Kodzis on Tue, 2005-09-13 15:47.

At the present akk@da is in a beta phase. There is no easy option to install it, no install scripts, so you will need to do many things to make it running.

Set the proper time on your OS. Do it before you will start using akk@da! Or better install and run NTP daemon which will keep your OS time up to date. See www.ntp.org for details.

Make sure your RRDtools was compiled with option --enable-perl-site-install (see ./configure --help from RRDtool sources).

Make sure MySQL server is running.

Install DBI perl module:

perl -MCPAN -e 'install DBI' &&
perl -MCPAN -e 'install CGI' &&
perl -MCPAN -e 'install CGI::Session' &&
perl -MCPAN -e 'install Pod::Escapes' &&
perl -MCPAN -e 'install Test::More' &&
perl -MCPAN -e 'install Pod::Simple' &&
perl -MCPAN -e 'install Test::Builder::Tester' &&
perl -MCPAN -e 'install Test::Pod' &&
perl -MCPAN -e 'install CGI::Compress::Gzip' &&
perl -MCPAN -e 'install Bit::Vector'

Manually install DBD::mysql perl module (http://search.cpan.org).
Manually install Net::SSLeay perl module (http://search.cpan.org).
Manually install CGI::Session::ExpireSessions perl module (http://search.cpan.org).
Then install all other required perl modules:

perl -MCPAN -e 'install Math::RPN' &&
perl -MCPAN -e 'install Cache::File' &&
perl -MCPAN -e 'install Digest::MD5' &&
perl -MCPAN -e 'install Error' &&
perl -MCPAN -e 'install HTML::Table' &&
perl -MCPAN -e 'install HTTP::Request::Common' &&
perl -MCPAN -e 'install IO::Socket::INET' &&
perl -MCPAN -e 'install IO::Socket::SSL' &&
perl -MCPAN -e 'install IPC::Open3' &&
perl -MCPAN -e 'install LWP::Parallel::UserAgent' &&
perl -MCPAN -e 'install Digest::SHA1' &&
perl -MCPAN -e 'install Digest::HMAC' &&
perl -MCPAN -e 'install Crypt::DES' &&
perl -MCPAN -e 'install Net::SNMP' &&
perl -MCPAN -e 'install Number::Format' && 
perl -MCPAN -e 'install Time::HiRes' &&
perl -MCPAN -e 'install XML::Simple' &&
perl -MCPAN -e 'install Net::IP' &&
perl -MCPAN -e 'install Net::DNS' &&
perl -MCPAN -e 'install Proc::ProcessTable' &&
perl -MCPAN -e 'install NetAddr::IP'

Install fping. Install nmap. Set suid bit on fping and nmap binaries to make it useable for user akkada.

chmod +s `which fping`
chmod +s `which nmap`

Install akk@da scripts (it should be installed in /akkada directory; if you need to change it you will have to do a lot of changes in etc/* akkada configuratin files and some changes in scripts):

groupadd akkada
useradd -g akkada -d /akkada akkada

Set password for user akkada. Add user akkada to the main group of the user your Apache server use.

Setup AKKADA env variable (e.g. in file /etc/profile):

export AKKADA=/akkada


cd /
wget http://akkada.tivi.net.pl/download/akkada-current.tar.gz
gunzip < akkada-current.tar.gz | tar xvf –
cd /akkada/bin
rm -f perl
ln -s `which perl` perl
mysql < akkada_db_create.sql
mysql akkada < akkada_db_dump.sql
mysql akkada < akkada_db_init.sql

Edit /akkada/etc/akkada.shell file and update variables: 

OSLogin
OSGroup
ApacheLogin
ApacheGroup
MYSQL
MYSQLDUMP

Run post_install.sh script to set proper rights for akk@da files: 

cd /akkada/bin
./post_install.sh

Update: mysqladmin, fping, nmap, ntpq paths in configuration files /akkada/etc/*. The easies way to do this is to use /akkada/bin/cfgcheck.pl for checking configuration syntax, cfgfindraw.sh for finding definition location and cfgdump.pl for displaying merged configuration on the screen. Problably this is the most difficult part of the startup procedure.

Edit etc/conf.d/System.conf configuration file and configure probes counts best for your network. Please do not use section "Modules". In section "Probes" for each probe configure processes count. For quick startup set 1 to all probes.

cat ${AKKADA}/etc/conf.d/System.conf   
{
    'Probes' => {
      'ucd_ext' => 1,
      'nic' => 1,
      'host_resources_process' => 0,
      'host_resources_system' => 1,
      'dns_server' => 1,
      'cisco_css_content' => 0,
      'softax_ima' => 0,
      'softax_ping' => 0,
      'node' => 1,
      'ucd_process' => 1,
      'hdd' => 1,
      'cisco_css_service' => 0,
      'ssl_generic' => 1,
      'cpu' => 1,
      'windows_service' => 0,
      'route' => 0,
      'cisco_css_owner' => 0,
      'cisco_dial_peer_voice' => 1,
      'dns_query' => 0,
      'tcp_generic' => 1,
      'snmp_generic' => 0,
      'icmp_monitor' => 0,
      'bgp_peer' => 0,
      'tcpip' => 1,
      'ram' => 1,
      'ntp' => 1,
    },
    'Modules' => {
      'tree_cache' => 1,
      'status_calc' => 1,
      'db_watch' => 1,
      'discover' => 1,
      'job_planner' => 1,
      'available' => 1,
      'icmp_monitor' => 1,
    }
}

After this you should be able to start akk@da (must be done from root account):

/akkada/etc/init.d/akkada {start|stop|restart}

Problems are reported in files:

/akkada/var/log/exc_text.log
/akkada/var/log/exc_xml.log

Now you need to configure Apache server httpd.conf file:

DocumentRoot "/akkada/htdocs"

<Directory "/akkada/htdocs">
    Options Indexes FollowSymLinks
    AllowOverride None
    Order allow,deny
    Allow from all
</Directory>

Add mod_perl configuration to httpd.conf file:

LoadModule perl_module modules/mod_perl.so
PerlRequire "/akkada/bin/startup.pl"
PerlPassEnv AKKADA
PerlPassEnv REMOTE_ADDR

PerlModule Runtime
<Location /gui>
SetHandler perl-script
PerlResponseHandler Runtime
</Location>

PerlModule Graph
<Location /graph>
SetHandler perl-script
PerlResponseHandler Graph
</Location>

# ContactsRuntime and CommentsRuntime works since version 0.70 - if you are installing
# previous version, do not put this sections into your Apache configuration
PerlModule ContactsRuntime
<Location /contacts>
SetHandler perl-script
PerlResponseHandler ContactsRuntime
</Location>
PerlModule CommentsRuntime
<Location /comments>
SetHandler perl-script
PerlResponseHandler CommentsRuntime
</Location>

PerlModule ImgsRuntime
<Location /imgs>
SetHandler perl-script
PerlResponseHandler ImgsRuntime
</Location>

Make sure the owner of all directories in /akkada/var directory and all files in /akkada/var/log directory is user you are running Apache server. Make sure Apache server has right to read directory /akkada/htdocs. Start Apache server- DO NOT USE service command, use /etc/init.d/httpd script or apachectl directly.

After this you should be able to access akk@da web GUI. In case there are problems with opening GUI check Apache error log file and akk@da log files described above.
