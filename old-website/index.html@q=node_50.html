Q: in Mozilla browser I do not see "refresh in X sec..." information when I use teeny skin mode
A: in Mozilla go to menu Edit -> Preferences -> Content. then check "Enable JavaScript". then click button "Advanced" and check "Change status bar text"

Q: discover process does not find any service of selected type
A: 1) check /etc/conf.d/System.conf, section "Probes", selected type must be > then 0 to make possible discover process
2) it's possible your host SNMP agent does not provide expected information

Q: Apache server does not start without any error information in log files
A: execure command: ipcs -s | grep apache | awk '{print $2}' | xargs ipcrm sem

Q: nm-job_planner.pl restarts all the time
A: check etc/akkada.conf definitions of ProbesMap and ProbesMapRev and System->{Probes} - probably you are tring to load np-* module which has missing ID map definition in ProbesMap and ProbesMapRev

Q: probe module does not start automatically with etc/init.d/akkada script but starts when manualy started with np-run.pl script
A: probe module during start prints some warnings on output - it cannot produce any output on STDOUT, STDERR to start automatically.

Q: I see in log file: Received tooBig(1) error-status at error-index 0
A: in host configuration try to set SNMP version to version 1

Q: when I use akk@da to monitor LAN switch its CPU utilization keeps over 80%; when I disable akk@da its ~ 3%
A: akk@da is quiet aggresive network monitoring software. e.g. np-nic.pl module, which is reponsible for network interface monitoring makes over 20 snmpgets eatch test on eatch monitored network interface; so if your device has a lot of network interfaces (e.g. modular HP ProCurve switch or Cisco Catalys 65xx) that is quite normal that device's CPU keeps high utilization; particulary if it's old device with old, not realy fast CPU; solution for that problem is to increase polling time of that device from default 60 seconds; the new value should be determine experimentally

Q: how much bandwidth needs akk@da?
A: it realy depend on type of monitored hosts; e.g. in my mixed environment with windows, linux, openvms servers and over 2.5k network interfaces in network devices akk@da monitors over 9k services and use for that ~1Mbps of bandwidth

Q: tcp_generic/ssl_generic - discovery process detects a lot of fake open TCP ports on hosts behind firewall. Observerd on hosts located befind CheckPoint Firewall with enabled SYNDefender.
A: add option "-T Pollite" to nmap definitions in AKK@DA configuration files (${AKKADA}/bin/cfgfindraw.sh nmap) and restart discover process

Q: I have a host with two SNMP agents - how to configure AKK@DA to read information from both agents?
A: possible since version 0.71. use syntax: xxx::yyy::zzz in snmp_% configuration options. count of agents is detected by snmp_version parameter. e.g.:

host has standard net-snmpd agent configured to work in version 3 and squid agent working in version 2c. do:

snmp_version=3::2
snmp_community=::public
snmp_user=userX::
snmp_authpassword=password::
snmp_privprotocol=des::

which will mean for AKK@DA:

I'v got 2 SNMP instances on the host - instance 0 -> version 3, and instance 1 -> version 2
In instance 0 host is using authPriv security model, both passowrds the same, user ak47, authentication protocol md5 (by default) and the private protocol des
In instance 1 host is using community publc

and another sample - host with 2 snmpv3 agents:

snmp_version=3::3
snmp_user=userX::userY
snmp_authpassword=passwordX::passwordY
snmp_privprotocol=des::des


Q: AKK@DA against Cisco CSS 110xx series device shows all network interfaces in status UNKNOWN.
A: there is some strange implementation of SNMP on those boxes. You need manualy modify perl module Net/SNMP/Message.pm:
find string: 'OBJECT IDENTIFIER length equal to zero' and rem that line:
