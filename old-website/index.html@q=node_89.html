v 0.71

Submitted by Piotr Kodzis on Sun, 2006-09-24 11:01.
  • changes

[* fixed; + added; - removed; @ changed]

* GUI - error parser bug for messages from forms processor

* snmp_generic - rittel templates threshold definitions syntax error

@ snmp_generic - cisco_slb_reals template added new real server states definitions

+ probe nic - possibility to disable discover of specified types of network interfaces

+ GUI - find entities possibility

+ probe node - a little linksys detection

+ probe_node - microsens detection

+ snmp_generic - added support for microsens CWDM modular system

* a few modules - some cosmetic changes to fix "uninitialized value" warnings

* probe host_resources_process - parameter host_resources_process_min didn't work well if set to 0

+ GUI contacts - added field alias in contact definition

+ GUI contacts - added option to integrate with external information system

+ GUI login - added login persistence

+ GUI added images chooser dialog box

* GUI bugs in cookies persistence

* tree_cache some data structure bugs with undef references

* GUI after moving all nodes from location 1 to location 2, in location 1 delete option was unavailable

+ GUI now it is possible to delete all branch of the tree with on click. in the past you had to delete manualy all nodes and locations from location you wished to delete

@ GUI service check period change wasn't effective until system restart. not it is effective immediately

@ probes data processing model was improved from the performance point of view

* GUI button "add node" was available on the "location" level where this operation is not permited

* GUI co-operation between tree and the main window. tree didn't focus on the right object when navigation source was from main window

* GUI options tab, "with services" checkboxes for "monitor" and "check period" was available also in prohibited context

+ GUI stat tab, "show/hide collected information" button session persistence added

+ GUI stat tab, "show/hide node information" button added

@ GUI context menus - selective load. till now all context menuses were loaded even if they wasn't needed

+ GUI full context menus support in tree,view an find modes

+ GUI two types of bouquet views of node services: list and detailed

+ nodes configuration && all SNMP probes - added support for hosts with multiple SNMP agents

* probes tcp_generic & ssl_generic used \n except \015\012 and for that reason scripts didn't work well against services tcp/ssl services located e.g. on Cisco content switches.

* akkada.pl uninitialized value made broken pipe and stopped akkada.pl script from time to time

@ icmp_monitor module added support for threads

* probe nic discovery procedure has duplicated network interfaces entities in case of Cisco boxes with CISCO-STACK-MIB support implemented

* mistaken tree cache directory definitions in some of the FormProcessor modules - due this sometimes changes done via GUI wasn't effective in a real time or until tree cache restart

* GUI node add form, bulk parameters didn't catch parameter ip

* GUI if group related to root has unreachable status, alarm was not presented

* probe softax_ima didn't dispatch SNMP datetime type into human readable format

@ GUI if node was in unreachable or nosnmp state, last check time information wasn't presented

@ GUI utils tab, now buttons with utilities depends on the type of selected node

* GUI log tab, GUI died if you tried to access log tab in empty view

+ GUI added tab contacts in node/service context to allow easier contacts mgmt

* GUI buttons "show alarm details", "show test result" didn't work well in views mode

+ command line entity modification tool ${AKKADA}/bin/entitymod.pl

@ GUI permissions subsystem, rights tab, now in column name is displaye full qualified (in the tree meaning) entity name

+ GUI node add form, added option to force AKK@DA to check defined SNMP configuration before it will add new node; if the test failed node is not added and you can fix your configuration

* GUI probe snmp_generic, bad defflation calculation if device report threshold == 0

+ probes nic and windows_service possibility to invert alarm which means, it is possible to configure specifiedy service to raise alarm if it is ok, and be quiet if it is down (e.g. to raise alarm when the backup ISDN link is up)

+ probe hdd, added option to disable low free i-nodes level alarms; resources mounted with CIFs shows 0 free i-nodes;

* probes tcp_generic & ssl_generic discover procedures protection agains firewall which defends from ports scan by showing all scaned ports as an open ports (e.g. CheckPoint NXG), which has made, AKK@DA tried to setup all those fake ports (thousands of ports...) in its configuration

@ all probes test scheduler added randomizer and weighted fair queues based on test duration time
